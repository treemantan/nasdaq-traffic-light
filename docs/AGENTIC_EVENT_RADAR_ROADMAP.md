# Agentic Event Radar 路线图

目标链路：

```text
News/Event Data
  -> Event Risk Tracking
  -> Market Confirmation / Validation
  -> Portfolio Exposure Mapping
  -> Agent Synthesis
  -> Macro Regime Radar Report
```

这条链路的目标不是把新闻简单做成情绪分数，而是把事件、价格验证、组合暴露和宏观框架放在同一个研究闭环里。最终产品应该回答：

- 哪些事件正在影响宏观叙事？
- 市场价格是否已经验证这些事件？
- 我的组合对这些事件暴露有多大？
- 多个信号是否相互确认，还是存在分歧？
- 需要人工复核的关键风险是什么？

## 当前完成度

整体上，系统已经完成了大约 `60%-65%` 的非 LLM 事件雷达基础设施；如果把“多 Agent synthesis / 自动研究判断”也算入终局目标，目前更接近 `40%-50%`。

已较稳定的部分：

- 新闻与政策事件可以进入报告。
- 政策、地缘、AI、关税、利率和能源等主题已有基础分类。
- 事件风险追踪可以聚合事件、权重、来源、组合暴露和市场验证。
- 市场验证已开始使用权益、美元、利率、波动率、黄金、油价和信用等价格行为。
- Full report 和 full email 已能展示事件风险追踪。
- 事件风险追踪已具备稳定 `event_id` 和第一版生命周期标签：`新事件`、`延续事件`、`待跟踪`。

仍缺的部分：

- 事件重要性仍偏规则驱动，缺少稳定的历史校准。
- 新闻质量、来源可信度和重复报道聚合还不够强。
- 市场确认目前是 cross-asset heuristic，不是完整因果验证。
- 组合暴露已经能映射 ticker 和权重，但行业、供应链、政策敏感度仍可深化。
- Agent Synthesis 目前还没有正式作为一层独立研究流程落地。
- 事件记忆仍是轻量版：已经能标记新事件/延续事件，但尚未完整追踪升级、缓和、失效和被市场证伪。

## 分层进度

| 层级 | 目标 | 当前状态 | 下一步 |
| --- | --- | --- | --- |
| News/Event Data | 抓取新闻、政策、公司事件、地缘事件和重要讲话 | 已有新闻卡片、政策/地缘事件、Google News/GDELT/白宫等来源 | 增加事件去重、来源分级、事件时间线 |
| Event Risk Tracking | 把新闻转成可追踪事件，而不是孤立 headline | 已有事件风险追踪模块，已显示事件 ID 与生命周期 | 增强重复事件合并、热度变化和失效判定 |
| Market Confirmation / Validation | 判断价格行为是否支持事件叙事 | 已接入初版 cross-asset validation | 增加历史同类事件对照、确认强度、证伪条件 |
| Portfolio Exposure Mapping | 映射组合对事件的直接/间接暴露 | 已能结合持仓权重和部分主题暴露 | 增加行业、供应链、国家、政策敏感度映射 |
| Agent Synthesis | 多角度综合判断，不依赖单一规则 | 尚未正式落地 | 先做 deterministic synthesis，再考虑 LLM/Agent |
| Macro Regime Radar Report | 把事件纳入宏观 regime 与组合风险解释 | 已接入网页和邮件报告 | 强化“事件改变了什么 / 尚未验证什么 / 组合需复核什么” |

## 建议推进顺序

### 1. 事件生命周期与去重

为每个事件生成稳定 `event_id`，按主题、来源、ticker、地区和时间窗口合并相似新闻。

当前已落地：

- 每个事件簇显示稳定 `event_id`，方便在网页、邮件和 JSON payload 中追踪。
- 多条证据合并的事件簇标记为 `延续事件`。
- 单条证据事件标记为 `新事件`。
- 暂无证据的占位事件标记为 `待跟踪`。

目标：

- 避免同一条新闻在报告中重复出现。
- 区分新事件、延续事件和已过期事件。
- 能写出“该事件已连续 3 天被市场确认”或“事件热度下降但价格压力仍未消除”。

### 2. 事件重要性评分

建立 `event_importance_score`，但保持解释透明，不直接伪装成精确概率。

可用特征：

- 来源可信度
- 是否涉及总统、财政部、Fed、公司 CEO、监管机构
- 是否影响多个资产类别
- 是否命中实际持仓
- 是否伴随成交量、波动率或信用利差确认
- 是否与当前宏观 regime 一致

输出：

```text
事件重要性：高 / 中 / 低
原因：命中 AI 半导体持仓、伴随 Nasdaq 回撤与 DXY 上行、来源为官方政策口径。
```

### 3. 市场确认强度

把当前“价格行为初步确认 / 分歧 / 未确认”升级为可审计结构。

建议字段：

- `supporting_signals`
- `conflicting_signals`
- `missing_signals`
- `confirmation_score`
- `invalidation_trigger`

例子：

```text
确认强度：中等
支持信号：DXY 上行、Nasdaq 回落、VIX 扩张
冲突信号：信用利差未扩大
证伪条件：未来 2-3 个交易日风险资产收复跌幅且 VIX 回落
```

### 4. 组合暴露增强

当前组合暴露主要是 ticker/主题权重层面。下一步应增加：

- 国家暴露：美国、英国、韩国、中国、欧洲
- 产业链暴露：AI compute、HBM、半导体设备、云资本开支、消费平台
- 政策敏感度：关税、出口管制、国防、利率、美元、能源
- 直接持仓与 ETF 穿透持仓的区分

输出应避免过度精确：

```text
组合对 AI capex 链条存在较高暴露，其中直接个股暴露为 X%，ETF 穿透暴露为 Y%，未穿透部分可能继续包含相关公司。
```

### 5. Agent Synthesis 第一版

不建议一开始就上复杂 LLM 多 Agent。更稳的路径是先做 deterministic synthesis：

- Macro Agent：事件是否改变宏观 regime？
- Policy Agent：政策风险是否升级？
- Market Agent：价格是否确认？
- Portfolio Agent：组合是否受到实质影响？
- Risk Agent：是否需要提醒或人工复核？

每个 Agent 先输出结构化 JSON，再由报告渲染为中文摘要。LLM 后续只负责“润色与综合”，不负责无证据判断。

### 6. 历史同类事件对照

当事件足够结构化后，可以加入历史参考。

例子：

- 关税升级事件后，Nasdaq、DXY、10Y、黄金的 1/5/20 日路径。
- Fed 鹰派 surprise 后，高估值成长股和短债 ETF 表现。
- AI 供应链负面事件后，NVDA/MU/AVGO/TSMC/ASML 反应。

注意：

- 历史对照只作为参考，不当作预测。
- 必须避免未来信息泄露。
- 需要显示样本数、独立事件数和异常样本。

## 报告展示目标

最终报告里，“事件风险追踪”应该长这样：

```text
事件：美国对半导体出口管制口径升级
重要性：高
市场验证：价格行为部分确认
组合暴露：AI/半导体链条权重较高，NVDA、AVGO、MU、半导体 ETF 相关
支持信号：Nasdaq 下跌、DXY 上行、VVIX 扩张
冲突信号：信用利差暂未扩大
需要复核：该事件是否改变 AI capex 交易的估值假设，还是仅为短期政策噪音
```

## 不建议现在做的事

- 不建议马上把所有新闻交给 LLM 自由判断。
- 不建议把事件分数直接并入总风险分，除非有明确校准。
- 不建议把单条新闻变成交易信号。
- 不建议用无法审计的情绪分数替代价格验证。

## 近期优先级

1. 事件去重与事件生命周期。
2. 市场确认强度结构化。
3. 组合暴露映射增强。
4. Agent Synthesis deterministic 版本。
5. 历史同类事件对照。
6. 再考虑 LLM synthesis 与更高级的 agent workflow。
